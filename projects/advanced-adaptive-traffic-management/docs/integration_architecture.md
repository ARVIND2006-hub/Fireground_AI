# Integrated Sensor-Driven Top

## Signal path

```text
Vehicle sensors -> 2-flop synchronization -> edge events -> demand scores
Pushbuttons -> synchronizers/debouncers -> emergency and pedestrian requests
Heartbeat + sensor-valid -> watchdog diagnostic latch
                            |
                            v
       external sensor valid AND frontend healthy AND NOT watchdog fault
                            |
                            v
                 traffic controller FSM
                            |
                            v
             low-voltage tabletop signal outputs
```

The integrated module is `rtl/traffic_management_physical_top.sv`. It is a separate sensor-driven demonstration top; the AXI processor-facing top remains available for software-controlled experiments.

## Fault policy

- A low external sensor-valid input sets the watchdog diagnostic fault.
- A heartbeat timeout also sets the watchdog fault.
- The watchdog fault invalidates the controller's sensor-valid input.
- The controller transitions to its latched fault state and commands both vehicle approaches red.
- Reset is required to recover the controller from the latched fault state; clearing the watchdog alone does not clear the controller state.

## Known engineering limits

- The sensor front end's `sensor_frontend_healthy` indicates only that reset is released; it is not a physical sensor self-test.
- Vehicle detection assumes the sensor pulse is wide enough to be sampled; narrow asynchronous pulses need a pulse stretcher or toggle/handshake capture circuit.
- A heartbeat is only meaningful if generated by the subsystem being monitored and routed correctly.
- Two-flop synchronizers reduce but do not eliminate metastability risk.
- This module is an educational tabletop design, not a safety-certified traffic controller. Do not connect it to public-road infrastructure.
